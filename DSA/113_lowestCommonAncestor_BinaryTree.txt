//First Approach -- see intuition below (till line 350)

class Solution {
    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
        if(root==null) return null; 

        if(root.val==p.val || root.val==q.val) return root;  //returning root , as p or q is root itself

        TreeNode left=lowestCommonAncestor(root.left,p,q);    //getting node if either any exists in left subtree (if not found, null)

        TreeNode right=lowestCommonAncestor(root.right,p,q);   //getting node if either any exists in right subtree  (if not found, null)


        if(left!=null && right!=null) return root;    //if nodes exists in left and right subtrees both 

        if(left==null) return right; 
        //if nodes doesn't exists in left subtree,,, so we return right which would be the possible lca then 

        else return left;   
        //if nodes doesn't exists in right subtree,,, so we return left which would be the possible lca then (as left gets the lca only --- dry run and see yourself)


    }
}





// LOWEST COMMON ANCESTOR (LCA)
//
// LCA means the lowest/deepest node in the binary tree
// which is an ancestor of both p and q.
//
// Example:
//
//          3
//         / \
//        5   1
//       / \ / \
//      6  2 0  8
//        / \
//       7   4
//
// For p = 5 and q = 1:
// LCA = 3
//
// For p = 5 and q = 4:
// LCA = 5
//
// ------------------------------------------------------------
//
// APPROACH: RECURSION / POSTORDER TRAVERSAL
//
// We solve the problem from bottom to top:
//
// 1. Check the current root.
// 2. Search for p or q in the left subtree.
// 3. Search for p or q in the right subtree.
// 4. Use the returned values to decide the LCA.
//
// ------------------------------------------------------------
//
// CODE:
//
// class Solution {
//     public TreeNode lowestCommonAncestor(TreeNode root,
//                                           TreeNode p,
//                                           TreeNode q) {
//
//         if(root == null) return null;
//
//         if(root.val == p.val || root.val == q.val) return root;
//
//         TreeNode left = lowestCommonAncestor(root.left, p, q);
//         TreeNode right = lowestCommonAncestor(root.right, p, q);
//
//         if(left != null && right != null) return root;
//
//         if(left == null) return right;
//         else return left;
//     }
// }
//
// ------------------------------------------------------------
//
// FULL INTUITION:
//
// 1. BASE CASE:
//
//    if(root == null) return null;
//
//    If the current subtree is empty,
//    then neither p nor q can be found here.
//
//    So we return null to the parent call.
//
// ------------------------------------------------------------
//
// 2. IF CURRENT ROOT IS p OR q:
//
//    if(root.val == p.val || root.val == q.val) return root;
//
//    If the current root itself is p or q,
//    return this root.
//
//    Why?
//
//    Suppose p is an ancestor of q:
//
//             5
//            / \
//           6   2
//              / \
//             7   4
//
//    If p = 5 and q = 4,
//    then 5 is the LCA.
//
//    Once we reach node 5,
//    we immediately return node 5.
//
//    This also handles the case where one target node
//    is the ancestor of the other target node.
//
// ------------------------------------------------------------
//
// 3. SEARCH IN LEFT SUBTREE:
//
//    TreeNode left = lowestCommonAncestor(root.left, p, q);
//
//    This recursively searches the left subtree.
//
//    The returned value can be:
//
//    - null       -> no target node found in left subtree
//    - a node     -> p or q, or the LCA was found there
//
//    Important:
//    We do not only search for p or q manually.
//    The recursive call itself returns useful information.
//
// ------------------------------------------------------------
//
// 4. SEARCH IN RIGHT SUBTREE:
//
//    TreeNode right = lowestCommonAncestor(root.right, p, q);
//
//    This does the same work for the right subtree.
//
//    After these two calls:
//
//    left  = answer/information from left subtree
//    right = answer/information from right subtree
//
// ------------------------------------------------------------
//
// 5. BOTH SIDES RETURN NON-NULL:
//
//    if(left != null && right != null) return root;
//
//    This is the most important condition.
//
//    If left is not null,
//    one target node was found in the left subtree.
//
//    If right is not null,
//    one target node was found in the right subtree.
//
//    Therefore, p and q are located in different subtrees.
//
//    So the current root is their Lowest Common Ancestor.
//
//    Example:
//
//             3
//            / \
//           5   1
//
//    For p = 5 and q = 1:
//
//    At node 3:
//
//    left  = node 5
//    right = node 1
//
//    Both are non-null,
//    therefore return node 3.
//
// ------------------------------------------------------------
//
// 6. ONLY RIGHT SIDE RETURNS NON-NULL:
//
//    if(left == null) return right;
//
//    If the left side returned null,
//    but the right side returned a node,
//    then the answer must be in the right subtree.
//
//    So we return right.
//
//    This returned value goes to the parent call.
//
// ------------------------------------------------------------
//
// 7. ONLY LEFT SIDE RETURNS NON-NULL:
//
//    else return left;
//
//    If the left side contains the answer,
//    return left.
//
//    If the right side is null,
//    there is no useful answer on the right.
//
// ------------------------------------------------------------
//
// IMPORTANT IDEA:
//
// The recursive function does not always return only p or q.
//
// It can return:
//
// 1. null
// 2. p
// 3. q
// 4. the actual LCA
//
// This is why the parent call can use the returned value
// to decide whether the current root is the LCA.
//
// ------------------------------------------------------------
//
// DRY RUN:
//
// Tree:
//
//             3
//            / \
//           5   1
//          / \ / \
//         6  2 0  8
//
// p = 5, q = 1
//
// At root 3:
//
//    root is not p or q.
//
//    Search left subtree:
//        returns node 5
//
//    Search right subtree:
//        returns node 1
//
//    left != null and right != null
//
//    Therefore return node 3.
//
// Answer = 3
//
// ------------------------------------------------------------
//
// ANOTHER DRY RUN:
//
// p = 5, q = 4
//
// At root 3:
//
//    Search left subtree.
//    Search right subtree.
//
//    The right subtree does not contain p or q,
//    so right = null.
//
//    The left subtree returns node 5.
//
//    Therefore root 3 returns node 5.
//
// At node 5:
//
//    root itself is p.
//
//    So return node 5 immediately.
//
// Answer = 5
//
// ------------------------------------------------------------
//
// WHY POSTORDER STYLE?
//
// We first solve:
//
//    left subtree
//    right subtree
//
// Then we use both results to decide the current root.
//
// Therefore, the logical order is:
//
//    LEFT -> RIGHT -> ROOT
//
// This is postorder-style recursion.
//
// ------------------------------------------------------------
//
// TIME COMPLEXITY:
//
// Every node is visited at most once.
//
// Therefore:
//
//    Time Complexity = O(n)
//
// where n is the number of nodes.
//
// ------------------------------------------------------------
//
// SPACE COMPLEXITY:
//
// Recursive calls use the call stack.
//
//    Space Complexity = O(h)
//
// where h is the height of the tree.
//
// For a balanced tree:
//
//    O(h) = O(log n)
//
// For a skewed tree:
//
//    O(h) = O(n)
//
// ------------------------------------------------------------
//
// SHORT SUMMARY:
//
// - null subtree returns null.
// - If root is p or q, return root.
// - Search both left and right subtrees.
// - If both sides return non-null, current root is LCA.
// - If only one side returns non-null, return that side.
// - If both sides return null, return null.
//
// FINAL PATTERN:
//
//    find answer in left
//    find answer in right
//    combine both answers at current root










// Second Approach -- using root to node paths 


// LOWEST COMMON ANCESTOR USING ROOT-TO-NODE PATHS
//
// ------------------------------------------------------------
//
// BASIC IDEA:
//
// The root-to-node path contains all ancestors of a node.
//
// If we find:
//
//     path from root to p
//     path from root to q
//
// then the LCA is the LAST COMMON NODE
// present in both paths.
//
// ------------------------------------------------------------
//
// EXAMPLE:
//
//              3
//             / \
//            5   1
//           / \ / \
//          6  2 0  8
//            / \
//           7   4
//
// Let:
//
//     p = 7
//     q = 4
//
// Root-to-p path:
//
//     3 -> 5 -> 2 -> 7
//
// Root-to-q path:
//
//     3 -> 5 -> 2 -> 4
//
// Common nodes:
//
//     3, 5, 2
//
// The LAST common node is 2.
//
// Therefore:
//
//     LCA = 2
//
// ------------------------------------------------------------
//
// FULL APPROACH:
//
// STEP 1:
//
// Create two lists:
//
//     path1 = root-to-p path
//     path2 = root-to-q path
//
// Initially both lists are empty.
//
// ------------------------------------------------------------
//
// STEP 2:
//
// Find the path from root to p.
//
// We use DFS/backtracking.
//
// At every node:
//
//     1. Add current node to path.
//     2. If current node is the target, return true.
//     3. Search left subtree.
//     4. Search right subtree.
//     5. If target is not found, remove current node.
//        This is backtracking.
//
// ------------------------------------------------------------
//
// STEP 3:
//
// Find the path from root to q.
//
// Use the same DFS/backtracking method.
//
// ------------------------------------------------------------
//
// STEP 4:
//
// Compare both paths from the beginning.
//
// Example:
//
//     path1 = [3, 5, 2, 7]
//     path2 = [3, 5, 2, 4]
//
// Compare:
//
//     path1[0] == path2[0] -> 3  common
//     path1[1] == path2[1] -> 5  common
//     path1[2] == path2[2] -> 2  common
//     path1[3] != path2[3] -> stop
//
// The last common node is 2.
//
// Return node 2.
//
// ------------------------------------------------------------
//
// WHY DOES THIS WORK?
//
// Both paths start from the same root.
//
// They remain common until the point where p and q
// move into different branches.
//
// The last node before they separate is the lowest
// common ancestor.
//
// ------------------------------------------------------------
//
// JAVA CODE:
//
// class Solution {
//
//     public TreeNode lowestCommonAncestor(TreeNode root,
//                                           TreeNode p,
//                                           TreeNode q) {
//
//         List<TreeNode> path1 = new ArrayList<>();
//         List<TreeNode> path2 = new ArrayList<>();
//
//         findPath(root, p, path1);
//         findPath(root, q, path2);
//
//         int i = 0;
//
//         while(i < path1.size() && i < path2.size()
//                 && path1.get(i) == path2.get(i)) {
//
//             i++;
//         }
//
//         return path1.get(i - 1);
//     }
//
//     boolean findPath(TreeNode root,
//                      TreeNode target,
//                      List<TreeNode> path) {
//
//         if(root == null) return false;
//
//         path.add(root);
//
//         if(root == target) return true;
//
//         if(findPath(root.left, target, path)
//                 || findPath(root.right, target, path)) {
//
//             return true;
//         }
//
//         // Target was not found in this subtree,
//         // so remove current node while backtracking.
//
//         path.remove(path.size() - 1);
//
//         return false;
//     }
// }
//
// ------------------------------------------------------------
//
// FINDPATH() INTUITION:
//
// Suppose we want to find node 7:
//
//              3
//             / \
//            5   1
//           / \
//          6   2
//             / \
//            7   4
//
// Start at 3:
//
//     path = [3]
//
// Go to 5:
//
//     path = [3, 5]
//
// Go to 6:
//
//     path = [3, 5, 6]
//
// Node 7 is not found in subtree of 6.
//
// Remove 6:
//
//     path = [3, 5]
//
// Now go to 2:
//
//     path = [3, 5, 2]
//
// Go to 7:
//
//     path = [3, 5, 2, 7]
//
// Target found.
//
// Return true.
//
// The final path contains only the nodes
// from root to the target.
//
// ------------------------------------------------------------
//
// IMPORTANT BACKTRACKING PATTERN:
//
//     path.add(root);
//
//     if(root == target) return true;
//
//     if(left search || right search) return true;
//
//     path.remove(path.size() - 1);
//
//     return false;
//
// We remove the node only when the target
// does not exist in that subtree.
//
// If the target is found, we do not remove the nodes,
// because we want to preserve the complete path.
//
// ------------------------------------------------------------
//
// WHY USE root == target?
//
// In this LeetCode problem, p and q are TreeNode objects.
//
// So we compare references:
//
//     root == target
//
// This checks whether both variables refer to
// the exact same tree node.
//
// Do not use:
//
//     root.val == target.val
//
// because two different nodes can have the same value.
//
// ------------------------------------------------------------
//
// DRY RUN:
//
// Tree:
//
//              3
//             / \
//            5   1
//           / \ / \
//          6  2 0  8
//            / \
//           7   4
//
// p = 7
// q = 4
//
// First path:
//
//     findPath(root, 7, path1)
//
//     path1 = [3, 5, 2, 7]
//
// Second path:
//
//     findPath(root, 4, path2)
//
//     path2 = [3, 5, 2, 4]
//
// Compare:
//
//     3 == 3 -> common
//     5 == 5 -> common
//     2 == 2 -> common
//     7 != 4 -> stop
//
// Last common node = 2.
//
// Answer = node 2.
//
// ------------------------------------------------------------
//
// EDGE CASE 1: ROOT IS p
//
//              3
//             / \
//            5   1
//
// p = 3
// q = 5
//
// path1 = [3]
// path2 = [3, 5]
//
// Common node = 3.
//
// Answer = 3.
//
// ------------------------------------------------------------
//
// EDGE CASE 2: p AND q ARE DIRECT CHILDREN
//
//              3
//             / \
//            5   1
//
// p = 5
// q = 1
//
// path1 = [3, 5]
// path2 = [3, 1]
//
// Last common node = 3.
//
// Answer = 3.
//
// ------------------------------------------------------------
//
// EDGE CASE 3: p AND q ARE THE SAME NODE
//
// If p == q,
// both paths are identical.
//
// The last common node will be that node itself.
//
// ------------------------------------------------------------
//
// TIME COMPLEXITY:
//
// Finding path to p:
//
//     O(n)
//
// Finding path to q:
//
//     O(n)
//
// Comparing both paths:
//
//     O(h)
//
// Total:
//
//     O(n) + O(n) + O(h)
//
//     = O(n)
//
// Therefore:
//
//     Time Complexity = O(n)
//
// ------------------------------------------------------------
//
// SPACE COMPLEXITY:
//
// Two paths store at most h nodes each:
//
//     path1 = O(h)
//     path2 = O(h)
//
// Recursive DFS call stack:
//
//     O(h)
//
// Therefore:
//
//     Space Complexity = O(h)
//
// For a balanced tree:
//
//     O(h) = O(log n)
//
// For a skewed tree:
//
//     O(h) = O(n)
//
// ------------------------------------------------------------
//
// MAIN DIFFERENCE FROM THE DIRECT RECURSIVE APPROACH:
//
// ROOT-TO-PATH APPROACH:
//
//     1. Find path to p.
//     2. Find path to q.
//     3. Compare paths.
//     4. Return last common node.
//
// DIRECT RECURSIVE APPROACH:
//
//     1. Search left subtree.
//     2. Search right subtree.
//     3. Combine returned answers.
//
// Both approaches take O(n) time.
//
// The path approach is easier to visualize
// because we explicitly see all ancestors.
//
// ------------------------------------------------------------
//
// SHORT SUMMARY:
//
// LCA using root-to-node paths means:
//
//     Find root -> p path.
//     Find root -> q path.
//     Compare both paths from the root.
//     The last common node is the LCA.
//
// CORE FORMULA:
//
//     LCA = last common node in both root-to-node paths
